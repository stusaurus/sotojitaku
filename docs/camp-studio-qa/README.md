## 実装と検証範囲

背景1枚と8個の透過WebPを新規制作した。固定カメラ、接地点を基準にした配置、CSS照明を使用。ホームや体験選択カードの既存写真とブランドロゴを継承した。初期背景273,114バイト。5幅それぞれで、家族・1泊・車なし・焚き火・コーヒーの操作で読み込んだworld内素材の合計は487,622バイト（Resource Timing encodedBodySize）。

同行者と人数を表す party_type と party_size は椅子を最大4脚まで図示し、詳細は実人数分を表示する。season は色調、stay はテントと照明、transport は荷物、experiences は選択内容に応じた道具と星、budget は既存計算の概算金額と予算表示に反映する。持ち物は計画上のイメージ。見送りや未定の道具を淡く表示し、詳細にエンジンの確認事項を示す。焚き火・安全装備・購入可否の判定は既存エンジンが担当する。

ブラウザごとに320、390、768、1024、1440pxを使用。モバイル幅は高さ844px、他は900px。GitHub Actions上のPlaywright、ja-JP、reducedMotion有効、計測・外部フォント通信を遮断。iOS実機の検証は未実施。

- 空の状態、人数に応じた椅子、日帰り時のテント非表示と夜の無効化、宿泊、移動、焚き火、概算と予算を確認。
- 7問、戻る、保存復元、個別タップと一覧、Escapeでの閉鎖、時間帯変更時の保存不変、所有・レンタル・購入・見送り、必須マット見送り時の完成ボタン無効化、料理・予算・計画完成・スケジュール、保存削除を確認。
- 世界素材の通信を遮断した状態でも質問を完了できた。シナリオ中のJavaScript例外は0。装備配置時に横スクロールなし。GA4と候補0件、危険な商品リンクは既存テストも実行した。
- JavaScript 196件中192件成功。失敗4件は変更前の同条件でも同じ実カタログの網羅性と候補の差別化。実カタログ5件を別扱いにする既存の回帰スイートは191/191。Python 330/330成功。
- 世界素材の転送量を記録した。Chromiumのヒープ値は各幅共通の丸め値で、増分の根拠には使えない。WebKitのヒープ、実利用者のCore Web Vitals、実機での連続描画・発熱は未測定。

## 美術レビュー

評価は5段階の開発者による目視評価。5は公開品質、4は基本体験成立、3は追加の美術調整が必要。

| 項目 | 点 | 観察結果 |
| --- | --- | --- |
| 世界観の一貫性 | 4 | 湖岸、山、道具の接地点を保ったまま時間帯が変わる。ケトルと天板の重なり、荷物の位置を修正した。 |
| 映像美 | 3 | 朝の山並みと木製家具はなじむ。夜は画面全体の減光が強く、火から周囲の椅子に届く反射光が弱い。 |
| 没入感 | 4 | 空の場所に道具が増え、完成した計画でも同じサイトが見える。椅子の向きと形に反復感がある。 |
| 操作の楽しさ | 4 | 家族・宿泊・焚き火は差が明快。季節の差は色調が中心。一部体験は同じ道具を共有する。 |
| 実用性 | 4 | 現物の確保と調達予定を区別できる。表示の小さな道具も一覧から確認できる。 |
| スマホUX | 4 | 320/390pxで時間切替と質問を両立。縦長の体験選択肢の下段を選ぶ際は風景が画面外になる。 |
