## Containment proposed in this PR (not yet deployed)

`npm run test:non-camp-live` executes **all** JS `*.test.mjs` files except exactly five time-sensitive CAMP live-catalog assertions in `tests/engine.test.mjs`. It verifies that these five names still exist; if they are renamed, this runner exits with an error rather than silently changing its scope.

Only the two CAR STAY workflows and FISHING workflow use the scoped runner. They still run their own JS/Python safety checks, product fit/coverage and catalog identity gates. A separate PR workflow verifies the scoped runner.

**CAMP refresh and daily Growth audit still run the full `npm test` and remain red until actual verified CAMP product coverage is recovered.** Never extend timestamps, weaken product eligibility tests, replace precise products with fuzzy results, or use unverified affiliate destinations just to make CI green.

## Real recovery criteria

1. Inspect the Worker/Rakuten API payload and item-page response under current credentials. Confirm exact seller SKU, matching canonical shop/item URL, product model, price, actual stock, images and official affiliate URL. `AUDIT_MISS` examples include a different store for a previously approved `naturum-outdoor` SKU. No unverified URL replacement.
2. Re-audit the missing CAMP items from independent live sale/spec evidence and commit only validated listing changes to `data/audited-products.json`; repair `refresh_worker.py` only for proven API schema changes.
3. On the new branch, run the full `npm test`, `npm run check`, Python tests and verify that CAMP scenarios contain suitable fresh offers. Review product changes and obtain approval before publication.
4. Re-run the CAMP scheduled workflow, Growth audit, CAR STAY, shared sync and FISHING runs; check successful commits, actual published JSON freshness and rendered recommendations. A successful CI alone is not proof of sales or clicks.

## User impact and limitations

Since the 49 CAMP listings have passed the seven-day verification window, the recommendation filter rejects them as stale. This can produce empty item choices but preserves user trust and purchase safety. This PR improves independent refresh reliability; it **does not** recover CAMP catalog availability, prove public deployment, or claim higher conversion.
