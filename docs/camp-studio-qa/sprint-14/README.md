# Sprint 14　湖畔でキャンプの計画を組み立てる

対象は Draft PR [#337](https://github.com/stusaurus/sotojitaku/pull/337) の CAMP。運営記録は [#248](https://github.com/stusaurus/sotojitaku/issues/248)。変更前は `0fb2b9829702813b6c40802ca7d728ce4cddfbe4`。最初に main、PR の変更とコメント、前回の Actions、既存の画像を照合し、変更前を両ブラウザの5幅で操作した。第1〜7問の意味・順序は共通。ブラウザではGitHubが作成したPRとmainの検証用結合を使い、変更前は当時のPRのHEADを直接開いた。

## 変更前に優先した3点

1. 最初の空の湖畔には道具を置く入口がなく、同行者は下の一覧から選んだ。第4・6問では道具の詳細を読めても、宿泊や過ごし方を変えるには別の回答欄に戻る必要があり、スマホでは置いた場所から視線が離れた。
2. 椅子の数やケトルの有無は正しかった。出入りが一瞬で終わり、道具を置いた手応えや、撤去した場所を追いにくかった。
3. 同じカメラと朝・夕・夜の色調は成立していた。テントから小物まで影の形が似ており、夕方の斜光やテーブル上のケトルと接点が合わない幅があった。

## 実装した3つの体験

- **風景から計画を選ぶ。** 第1問の「椅子を置く」から同行者を選ぶと、ひとりなら1脚、家族なら4脚の椅子が並ぶ。選択肢は押したときだけ開き、選択後は閉じる。第4問の「テント泊」を押すと日帰り・1泊が切り替わる。日帰りでは夜のプレビューを閉じる。第6問の「朝コーヒー」「焚き火」は、設置場所を浮かべた印で選択・解除できる。カードと同じ回答処理で保存し、明示的に選んだ時間帯を保つ。元の道具を押すと装備の状態を確認できる。
- **置いて、片づける。** テントは裾から520msで立ち上がり、椅子や道具は短く着地する。撤収時の描画だけを200ms残し、操作対象からは直ちに外す。素早く選び直した場合も重複しない。炎は最初だけ揺らぎ、朝のケトルは画面内で湯気を出す。動きを減らす設定や低性能の手がかりを受けた端末では静止画で操作できる。
- **道具を地面と時間帯になじませる。** 同じ写真とカメラ、既存の水面・灯りを生かす2.5D構成。写真の輪郭から朝・夕・夜で向きと長さの異なる影を描き、ケトルの底をテーブルの高さに合わせた。夜はテントや椅子の縁の発光を抑え、焚き火とランタンの地面の照り返しを残した。燃料を見送ったプランでは炎と湯気を消し、装備一覧には準備状態を残す。

環境内に操作の手掛かりを置く発想と、キャンプ用品を組み合わせると生活の場がどう変わるかを検討した。本画面の配置・写真・ロゴは SOTOJITAKU の既存資産を使っている。[任天堂の開発者によるGDC講演](https://gdcvault.com/play/1024562/Change-and-Constant-Breaking-Conventions) · [Snow Peak の Layout System](https://www.snowpeak.com/pages/layout-system)

## 描画と応答の実測

Chromiumの同じシナリオを実行した単回のラボ値。先行ビルドと今回のランナーは別。以下の復号時間は「キャンプをつくる」から背景画像の復号完了まで。LCPはランディングのナビゲーションの値。CLSは操作直後を除くレイアウト移動の合計。

| 条件 | 湖畔の復号 前 → 後 | 画像数・合計 | CLS 前 → 後 | 長いタスク合計 前 → 後 | 初期ナビゲーションLCP 前 → 後 |
| --- | --- | --- | --- | --- | --- |
| 390px・通常 | 35 → 57ms | 9枚・512,768 B（前後同じ） | 0 → 0 | 0 → 0ms | 108 → 100ms |
| 1440px・通常 | 28 → 48ms | 9枚・512,768 B（前後同じ） | 0 → 0 | 0 → 0ms | 40 → 128ms |
| 390px・湖畔だけ1.2秒遅延 | 1228 → 1241ms | 9枚・512,768 B（前後同じ） | 0 → 0 | 0 → 0ms | 104 → 68ms |

湖畔の体験を押してから2回目の描画コールバックまでの記録範囲は、全5幅でChromium 18〜33ms、WebKit 114〜351ms。WebKitの390pxでだけ今回の2サンプルは変更前の147・209msに対して335・351msと遅かった。他の4幅はいずれも今回の最大値が変更前を下回った。各幅2サンプルのため、実機で再計測する。実利用者のINPやフレームレートとは異なる指標。画像を意図的に遅らせた条件でも先に回答できた。Reduce Motion時と2コア相当のヒントでは設営アニメーションを停止し、通常の4コア相当では再生を確認。朝の湯気は湖畔をスクロール範囲の外に出すと停止した。

開発途中、輪郭をCSSマスクで作ると同じ写真を再要求して675,064 Bになった。元画像の同じリクエストを再利用する方式で162,296 Bを削減した。画像合計525,000 Bを超えると失敗する回帰検査を追加した。
